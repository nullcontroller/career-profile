## キャリア概要

大学では自然言語処理を扱い、人が用いる言語情報をコンピュータで処理する技術に触れました。その後はソフトウェア開発・プロジェクトマネジメントを経験し、近年は生成AI / RAGを用いて、自然言語や業務Knowledgeを実際の業務システムへ活用する取り組みに発展しています。

2016年より富士ゼロックス株式会社（現 富士フイルムビジネスイノベーション株式会社）にて、ソフトウェア開発、要件定義・要件分析、プロジェクトマネジメント、生成AI / RAGを用いたQAシステム開発、レガシーシステムの保守・モダナイゼーションに携わってきました。

キャリアの前半では、C# / .NETを用いたWindows業務ソフトウェアや複合機関連ユーティリティの開発を担当し、既存製品との互換性や外部システムとの連携を考慮しながら、設計・実装・評価・保守を経験しました。

その後、複合機製品開発のプロジェクトマネージャーとして約2年8か月、複数サブチームを横断した計画、進捗、課題、リスク、品質問題への対応を担当しました。

近年は、生成AI / RAG / AI Evaluation / Human in the Loop / Knowledge・Context設計を中心に、AIを既存業務・既存システムへ組み込むための設計・検証に取り組んでいます。

現在は、既存システムの仕様・制約・影響範囲を整理し、

**何を作るか・作らないか  
何を残すか・変えるか  
何を統合・移行し、どう廃止するか**

までを含めて、実装可能な設計へ落とし込むことを重視しています。

AIについても導入自体を目的とせず、業務目的からAIを使う領域・使わない領域を判断し、AI・人間・既存システムの役割と責任境界を設計することを重視しています。

C# / .NETを用い、製品ごとに異なる仕様・制約・連携条件を理解しながら、詳細設計、実装、評価、保守を担当しました。

この時期に、単に新規機能を作るだけではなく、既存仕様、他システムとの依存関係、互換性を理解したうえで変更する経験を積みました。

# Applied AIの考え方

大学で自然言語処理を扱った経験を背景に、現在は生成AI / RAG / Knowledge・Context設計を用いて、人が持つ知識や自然言語情報を業務システムで活用することに取り組んでいます。

ただし、AI導入そのものを目的にはしていません。

業務目的を起点として、

- どの業務へAIを適用するか
- AIを使わない方がよい処理は何か
- AIへ任せない判断は何か
- AI・人間・既存システムをどう役割分担するか
- どのKnowledge / ContextをAIへ与えるか
- AI出力をどう評価するか
- どの条件で人間へ戻すか
- 本番運用後にどう再評価・改善するか

までを、一つの業務システムとして設計します。

AIの出力は原則として最終成果物ではなく、**人間または既存システムによる確定前の中間成果物**として扱います。

AIの能力だけでなく、責任境界、評価、運用、保守性を含めて実運用可能な構成へ落とし込むことを重視しています。

# Applied AIの経験領域

## RAG / Knowledge Architecture

仕様書やナレッジが十分に整備されていないレガシーソフトウェアについて、UI操作、ソースコード、既存資料から仕様・操作情報を再構築し、RAGで利用可能なKnowledgeとして構造化しました。

設計対象には、

- Knowledgeの対象
- 検索単位
- 回答根拠
- 情報更新
- AIが回答可能な範囲

までを含みます。

## AI Evaluation / Human in the Loop

AI出力については、単純な正答率だけではなく、

- 根拠との整合性
- 既存仕様との整合性
- 前提条件
- 影響範囲
- 情報不足時の挙動
- 人間への差し戻し条件
- 人間が判断するために必要な情報

を評価対象としています。

Human in the Loopについても、単に承認者を置くのではなく、

**判断に必要な知識・情報・権限を持つ人間を、適切な判断点へ配置する**

という考え方を重視しています。

## AI-Assisted Software Engineering

AIを実装そのものの代替としてではなく、判断材料を早く・広く集めるために利用しています。

最終的な設計判断、変更影響の判断、採用判断は人間が担います。

AIの出力を中間成果物とし、既存仕様との整合、変更影響、最終的な設計・採用判断は人間が担います。

# 希望する役割

今後は、

**自社側でAIプロダクトや既存システムを継続的に担当し、企画・設計から本番運用・継続的な改善まで長期的に関われる技術職**

を志向しています。

作って終わるのではなく、継続的に担当する対象について理解を蓄積し、運用や利用から得た知見を設計へ戻しながら改善を続ける仕事を好みます。システムや業務の前提が変わったときに、その変化を踏まえて設計を見直し、長期的に改善していける環境を重視しています。個別の実装や運用で得た理解を、システム全体の判断やアーキテクチャの改善へつなげ、将来的なシステム企画・IT企画にも関わっていきたいと考えています。

主な関心領域は、

- Applied AI
- AIを用いたシステム企画・業務設計
- Enterprise AI Architecture
- AIプロダクトの企画・設計・運用改善
- システム企画
- システムアーキテクチャ
- 自社製品・自社システムの継続的な改善
- 将来的なIT戦略・IT企画

です。

PM経験やチーム運営経験はありますが、今後はPeople Managementをキャリアの中心には置かず、技術・設計判断に直接関与する役割を希望しています。

# 志向しない役割・環境

以下を主責務とする役割は志向していません。

- 顧客常駐やFDE
- プリセールス・営業
- People Management
- PMO・進捗管理
- 英語を日常的に使用することが前提の環境

PMやPeople Managementの経験自体を避けているわけではなく、それらを経験した結果、**技術・設計・課題解決へ直接関与する方が、自身の強みを発揮できると判断しています。**
