## 第3章　GitHub Copilotと人間で実現方法を具体化する

第2章では、異常時は安全側へ倒し、正常性を確認できない場合は後続処理を停止するという設計方針を確定した。

次に必要なのは、その方針を既存コードのどこへ、どのように組み込むかを決めることである。

この段階では、例えば次の点が未確定だった。

- どこでエラーを検出するか
- どこで後続処理を止めるか
- どの既存処理へ分岐を追加するか
- 外部システム連携の前に、どこで異常状態を遮断するか

そこでGitHub Copilotを利用し、既存コードを参照しながら実現方法を具体化した。

### GitHub Copilotで関連コードを探索する

レガシーシステムでは、暗号化・復号、レジストリ読出し、外部システム連携などの処理が複数箇所に分散していた。

同じ暗号化パスワードを扱う処理でも、起動時、設定変更時、特定機能の実行時、外部システム連携直前など、呼び出されるタイミングが異なる。

そのため、単純な文字列検索だけでは、変更対象や影響範囲を十分に把握できなかった。

そこでGitHub Copilotへ自然言語で質問し、関連する処理、呼出し関係、分岐、後続処理を探索した。

![](/assets/imported/zenn/d876e5e906671969.png)

ここでは、GitHub Copilotを単なるコード生成AIとしてではなく、

> プロジェクト全体を意味から探索し、実装候補を洗い出すための支援手段

として利用した。

### AIの指摘をそのまま修正対象にしない

GitHub Copilotによる調査では、既存コードについて複数の懸念も示された。

例えば、コードだけを見ると、

- 分岐が不足しているように見える
- 初期化が不十分に見える
- 呼出し順序に問題があるように見える
- 状態管理が粗く見える

といった箇所である。

しかし、AIが問題と判断した箇所が、そのまま実際の不具合や修正対象になるとは限らない。

![](/assets/imported/zenn/07d394723ec449d0.png)

そこで、AIが懸念として挙げた箇所について、人間が実際のコードと運用条件を確認した。

確認したのは、主に次の点である。

| 確認観点 | 内容 |
|---|---|
| 到達条件 | その処理が実際にどの条件で実行されるか |
| 前提状態 | 前段処理で何が保証されているか |
| 呼出し関係 | どの処理から、どの順序で呼ばれるか |
| 値の利用 | 実際にどの値が後続処理で利用されるか |
| エラー後の制御 | 異常発生後に処理がどこまで進むか |
| 運用条件 | 実際の利用方法では問題が顕在化するか |
| 外部影響 | 外部システムへ誤った情報が渡る可能性があるか |

その結果、設計上の粗さはあっても、今回の変更では問題にならない箇所は改修対象から外した。

一方で、異常状態のまま後続処理へ進む可能性がある箇所や、今回の暗号方式変更によって新たに影響を受ける箇所については、対応が必要と判断した。

この工程で重要だったのは、

> AIが示した懸念を、修正指示ではなく調査候補として扱った

ことである。

### 実現方法をコード上で具体化する

調査結果を基に、既存コードへの組込み方法を具体化した。

最終的には、次の方針へ落とし込んだ。

| 対象 | 実現方法 |
|---|---|
| 暗号化・復号API | 戻り値を確認し、失敗時は後続処理へ進ませない |
| 復号失敗 | 取得した値を平文パスワードとして利用しない |
| レジストリ異常 | 異常を検出した時点で処理を継続せず、利用者へ案内する |
| 復旧案内 | アンインストールと再インストールを基本とする |
| 外部システム連携 | 連携前に異常状態を遮断する |
| 既存正常系 | 大きく変更せず、必要な分岐のみ追加する |
| 責務範囲 | OSやWindowsプロファイルなどは本システムの責務外とする |

GitHub Copilotには、関連コードの探索、呼出し関係の整理、実装候補の提示を担わせた。

一方、人間は、AIが示した内容を実際のコードと運用条件に照らして確認し、どの箇所を本当に変更するか、どの実装方法を採用するかを決定した。

これにより、第2章で確定した設計方針を、既存コードへ適用可能な実現方法へ落とし込むことができた。

### 本章の位置付け

本章で行ったのは、GitHub Copilotに実装を決めさせることではない。

> GitHub Copilotでコード上の候補を広く探索し、人間が実際のコードと運用条件を基に必要な変更だけを選び、設計方針を具体的な実装方法へ変換する工程

である。
